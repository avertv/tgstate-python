# tgState V2 — Версия на Python

[![Python Version](https://img.shields.io/badge/python-3.11+-blue.svg)](https://www.python.org/downloads/)
[![Framework](https://img.shields.io/badge/Framework-FastAPI-green.svg)](https://fastapi.tiangolo.com/)
[![Docker](https://img.shields.io/badge/Docker-Ready-blue.svg)](https://www.docker.com/)

Ссылка на оригинальный проект `tgState`: [csznet/tgState](https://github.com/csznet/tgState), переработан с использованием FastAPI.

##### Добавлена страница веб-диска для управления файлами.

##### Добавлена страница хостинга изображений для удобного копирования ссылок.

##### Добавлено автоматическое распознавание файлов в группе для отображения на веб-диске.

## Возможности

* **Безлимитное хранилище**: Использует облачный сервис Telegram в качестве вашего личного файлового хранилища.
* **Вечный хостинг картинок**: Пока работает сервис — хостинг изображений никогда не перестанет работать.
* **Современный UI**: Лаконичный, отзывчивый и удобный веб-интерфейс для загрузки и управления файлами.
* **Простая развертка**: Всего за несколько минут с помощью Docker или прямой запуск локально.
* **Прямые ссылки**: Генерирует прямую ссылку, которой можно поделиться, для каждого загруженного файла.
* **Поддержка больших файлов**: Автоматическая обработка загрузки больших файлов частями (чанками).
* **Защита паролем**: Опциональный механизм защиты паролем для обеспечения безопасности вашего веб-интерфейса.

## Быстрый старт

Рекомендуется использовать Docker для развертывания `tgState` — это самый простой и быстрый способ.

### Развертывание через Docker

```bash
docker run -d \
  --name tgstate \
  -p 8000:8000 \
  -e BOT_TOKEN="123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11" \
  -e CHANNEL_NAME="@my_test_channel" \
  -e PASS_WORD="supersecret" \
  -e BASE_URL="[https://my-service.com](https://my-service.com)" \
  -e PICGO_API_KEY="supersecret(опционально, удалите эту строку если не нужно)" \
  -e TG_API_ID="123456" \
  -e TG_API_HASH="your_telegram_api_hash" \
  -e TELEGRAM_SYNC_SESSION="tgstate-sync" \
  -e TELEGRAM_SYNC_SESSION_STRING="your_telegram_user_session_string" \
  -e TELEGRAM_RECONCILE_INTERVAL="60" \
  ghcr.io/justhil/tgstate-python:latest
```

### Локальная разработка и запуск

Если вы хотите запустить `tgState` напрямую в локальном окружении:

1. **Клонируйте проект и перейдите в директорию**:

   ```bash
   git clone [https://github.com/your-repo/python-tgstate.git](https://github.com/your-repo/python-tgstate.git)
   cd python-tgstate
   ```

2. **Создайте и активируйте виртуальное окружение**:

   ```bash
   # Создание виртуального окружения
   python -m venv venv
   # Активация виртуального окружения (Windows)
   venv\Scripts\activate
   # Активация виртуального окружения (Linux/macOS)
   # source venv/bin/activate
   ```

3. **Установите зависимости**:

   ```bash
   pip install -r requirements.txt
   ```

4. **Создайте конфигурационный файл `.env`**: По аналогии с разделом Docker создайте и настройте файл `.env` в корневой директории проекта.

5. **Запустите приложение**:

   ```bash
   uvicorn app.main:app --reload
   ```

   Если домен не настроен, приложение будет работать по адресу `http://127.0.0.1:8000`.

## Конфигурация (Переменные окружения)

`tgState` настраивается через переменные окружения, приложение автоматически загружает эти переменные из файла `.env` в корневой директории.

| Переменная | Описание | Обязательна | Значение по умолчанию |
| --------------- | ------------------------------------------------------------ | -------- | ----------------------- |
| `BOT_TOKEN` | Ваш токен Telegram Bot API. Можно получить у [@BotFather](https://t.me/BotFather). | **Да** | `None` |
| `CHANNEL_NAME` | Целевой чат/канал для хранения файлов. Может быть `@username` публичного канала. | **Да** | `None` |
| `PASS_WORD` | Пароль для защиты доступа к веб-интерфейсу. Если оставить пустым, доступ к приложению будет открытым, без пароля. | Нет | `None` |
| `BASE_URL` | Публичный URL вашего сервиса. Используется для генерации полных ссылок на скачивание. | Нет | `http://127.0.0.1:8000` |
| `PICGO_API_KEY` | API-ключ для интерфейса загрузки PicGo. | Нет | `None` |
| `TG_API_ID` | Telegram MTProto `api_id`, используется для создания MTProto-клиента. | Нет | `None` |
| `TG_API_HASH` | Telegram MTProto `api_hash`, используется для создания MTProto-клиента. | Нет | `None` |
| `TELEGRAM_SYNC_SESSION` | Имя сессии Bot MTProto. | Нет | `tgstate-sync` |
| `TELEGRAM_SYNC_SESSION_STRING` | Строка сессии пользователя, используемая для заполнения истории при старте. | Нет | `None` |
| `TELEGRAM_RECONCILE_INTERVAL` | Базовый период сверки удалений MTProto; при превышении 1 000 / 10 000 файлов автоматически увеличивается минимум до 300 / 900 секунд. | Нет | `60` |

### Пример конфигурации синхронизации истории Telegram

Если необходимо автоматически восстанавливать список файлов в веб-интерфейсе из истории сообщений Telegram после перезапуска, вы можете добавить в `.env` следующие настройки:

```env
TG_API_ID=123456
TG_API_HASH=your_telegram_api_hash
TELEGRAM_SYNC_SESSION=tgstate-sync
TELEGRAM_SYNC_SESSION_STRING=your_telegram_user_session_string
TELEGRAM_RECONCILE_INTERVAL=60
```

Назначение каждой настройки:

- `TG_API_ID` / `TG_API_HASH`: Учетные данные приложения Telegram для создания соединения MTProto.
- `TELEGRAM_SYNC_SESSION`: Имя сессии во время работы бота, используется для хранения файла сессии на стороне бота.
- `TELEGRAM_SYNC_SESSION_STRING`: Строка сессии пользователя, используется **только при запуске** для сканирования исторических файлов.
- `TELEGRAM_RECONCILE_INTERVAL`: Базовый период сверки удалений. Когда количество файлов превышает 1 000 строк, выполняется не чаще одного раза в 5 минут; когда превышает 10 000 строк — не чаще одного раза в 15 минут для снижения количества запросов к Telegram и нагрузки на сервер.

## Важно относительно паролей

1. **Оба пароля 【НЕ】 установлены**:
   - **Режим**: Полностью открытый.
   - **Результат**: Как через Picgo/API, так и через веб-страницу **можно загружать напрямую**, без каких-либо учетных данных.
2. **Установлен только 【Пароль Picgo】**:
   - **Результат**: Запросы на загрузку с веб-страницы будут разрешены безусловно. Запросы от Picgo/API будут разрешены после проверки.
3. **Установлен только 【Пароль для входа】**:
   - **Результат**: Загружать с веб-страницы смогут только **авторизованные** пользователи веб-страницы. Запросы от Picgo/API будут разрешены безусловно.

## Инструкция по использованию

1. **Перейдите в веб-интерфейс**: После запуска приложения откройте в браузере `http://127.0.0.1:8000` (или настроенный вами `BASE_URL`).

2. **Проверка пароля**: Если вы установили `PASS_WORD` в файле `.env`, приложение сначала перенаправит вас на страницу ввода пароля. После ввода правильного пароля вы сможете получить доступ к главному интерфейсу.

3. **Загрузка файлов**: В главном интерфейсе нажмите на область загрузки, чтобы выбрать файл, или перетащите файл непосредственно в окно загрузки. После успешной загрузки файл появится в списке файлов ниже.

4. **Загрузка через группу**: Поддерживается пересылка в группу для загрузки, поддерживаются файлы и фотографии размером менее 20 МБ (ограничение официального Telegram).

5. **Получение ссылки**: Для каждого файла в списке файлов отображается его имя, размер и дата загрузки. Нажмите на имя файла, чтобы скопировать прямую ссылку на скачивание этого файла.

6. **Получение ссылки в группе**: Ответьте словом `get` на сообщение с файлом в группе, чтобы получить ссылку на скачивание.

## Руководство по настройке PicGo

### Предварительные требования

1. Установите плагин `web-uploader`.

### Основные настройки

1. **Имя конфигурации хостинга**: Любое.

2. **Адрес API**: Укажите адрес загрузки, предоставляемый вашим сервисом. Локально это `http://<IP_вашего_сервера>:8000/api/upload`.

3. **Имя POST-параметра**: `file`.

4. **Имя JSON-параметра**: `url`.

5. **Пользовательские заголовки (Custom Headers)**: `{"x-api-key": "PICGO_API_KEY"}` (опционально, рекомендуется) (один из двух способов проверки).

6. **Пользовательское тело (Custom Body)**: `{"key":"PICGO_API_KEY"}` (опционально, рекомендуется) (один из двух способов проверки).

### Интерфейс удаления PicList

В проект добавлены два интерфейса удаления `/api/delete` и `/api/piclist/delete`, поддерживающие разбор удаляемого файла из `file_id`, `url`, `imgUrl`, `path` или `fullResult` в теле запроса.

Интерфейс загрузки также дополнительно возвращает:

- `file_id`
- `delete_api`
- `fullResult`

Если вы вызываете интерфейс удаления через систему скриптов в PicList, продолжайте использовать `x-api-key`, настроенный при загрузке.

### Пример скрипта синхронизации удаления для PicList

Если вы включили скрипт после удаления в PicList, вы можете напрямую вызвать `/api/delete`:

```javascript
async function main(ctx, extra) {
  if (!extra || !extra.galleryItem) {
    return ctx
  }

  await axios.post(
    'https://your-domain/api/delete',
    {
      list: [extra.galleryItem]
    },
    {
      headers: {
        'x-api-key': 'your_picgo_api_key',
        'Content-Type': 'application/json'
      },
      timeout: 30000
    }
  )

  return ctx
}
```

Описание:

- Замените `https://your-domain/api/delete` на адрес вашего собственного сервиса.
- Замените `x-api-key` на настроенный вами `PICGO_API_KEY`.
- `extra.galleryItem` будет содержать такую информацию, как `url`, `file_id`, `fullResult` и т. д. из результатов загрузки, и сервер автоматически разберет и удалит соответствующий файл.

### Описание восстановления истории Telegram и удаления в группах

Если вы хотите автоматически восстанавливать список файлов в веб-интерфейсе из истории сообщений Telegram после перезапуска сервиса, вы можете дополнительно настроить:

- `TG_API_ID`
- `TG_API_HASH`
- `TELEGRAM_SYNC_SESSION_STRING`

Эти настройки используются **только для заполнения истории при старте**.

Текущая версия **не предоставляет** функцию «ручного удаления сообщений в группе с синхронным удалением в веб-интерфейсе в реальном времени».

Причина заключается в том, что для стабильной работы этой функции обычно требуется постоянно работающий **процесс пользовательской сессии** для непрерывного прослушивания или сверки. Проект не использует этот подход в основном потому, что:

- Постоянно работающая пользовательская сессия может увеличить риски контроля безопасности аккаунта и его блокировки.
- Сложность развертывания выше, а затраты на обслуживание также выше.

Таким образом, рамки текущей версии таковы:

- `TELEGRAM_SYNC_SESSION_STRING` отвечает только за сканирование истории и восстановление списка веб-интерфейса при запуске.
- Удаление через веб-страницу и PicList по-прежнему может нормально синхронизироваться с Telegram.
- Ручное удаление сообщений в группе Telegram не будет в реальном времени обратной записью удалять файлы из списка веб-интерфейса.
